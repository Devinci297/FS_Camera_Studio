# FS Camera Studio 0.4.0 verification record

Date: November 7, 2026. This record separates automated release verification from live MSFS acceptance.
Earlier evidence remains unchanged.

## Source and build

- Release version: `0.4.0` (`VERSION`, package manifest and panel metadata agree).
- Built from `4081ae2` on the release PC with MSFS 2024 SDK **1.8.1**, the SDK every flown build since 5 November
  used. The host refresh is committed as `75a114b` and `ddc77bf` (the second stores the CRLF bytes the receipt hashes).
- Reviewed host: `package/validated-host`, refreshed with `stage-v0.4.py --host` from the `tools\package.ps1 -Compile`
  build of the frozen module; receipt `package/validated-host.json`, baseline `0.4.0-release`, 25 files.
- Module output: `build/wasm/release-0.4.0/FSCameraStudio.wasm` (sha256 begins `41dd5150`).
- Staged package: `build/release/0.4.0/fs-camera-studio`, 26 files, identical to `build/release/0.4.0/staged.json`.
- Installer compiler: Inno Setup 6.7.3, Authenticode signature valid (Pyrsys B.V.).
- The illustrated manual (19 pages) was built with ReportLab in a cloud checkout of `4081ae2`, because the release PC has
  no ReportLab, then copied to the PC. Its sha256 was checked on arrival.

## Results

- **Native:** 309 tests passed, 0 failed; 75,190 checks (CTest passed).
- **UI:** 57 of 59 `ui/tests` files pass in headless Chromium against `ui/`. `updates.test.cjs` failed only because it
  hard-coded 0.3.1 as the newer release; it now offers 0.4.1 and passes. `icon-pack.test.cjs` needs a
  `build/review` packaged build and fails the same way on the pre-release branch.
- **Manual:** pages 16 to 19 (camera feel, cinematic and drones, spotting, mini traffic / gamepad / pop out) were
  rendered with Poppler and inspected. Screenshots are browser demo fixtures, not live simulator captures.
- **Staging:** `stage-v0.4.py` was also dry-run in a scratch copy before the PC build; `build-installer.py` passed its
  package, layout and version checks there.
- **Installer tests:** `tools/test-installer.py` was **not run**. It requires `build/review/hat-release/installed.json`,
  a receipt from the old development clone, which this clone does not have. `installer/CameraStudio.iss` is
  unchanged since 0.3.0, whose shipping installer passed nine isolated scenarios.

## Simulator coverage and live checks still pending

Development builds of the same UI and module code (version 0.3.0 labels, `tools\package.ps1 -Compile`) were flown:
phase 1 and phase 2 about 20 minutes each without a crash, and the first spotting build 32 minutes without a crash
with FSLTL traffic. The final development build (`8d5a7fa`) was installed on the PC; the 0.4.0 installer itself has
not yet been installed or flown.

Still pending: head movement strength, mounted camera pitch direction, binoculars below 30 degrees, cinematic phase
thresholds, temporary airport vantage points, free drone flight and terrain floor, gamepad axis detection and aircraft
masking, chase and fly-by smoothness on moving traffic, runway end selection, live spot editing, Pop out visibility,
the mini Traffic filter bar, and a setup upgrade from 0.3.0. [Qualification steps](../qualification.md) describe these
checks. Neither browser screenshots nor installed-file hashes constitute live simulator acceptance.
