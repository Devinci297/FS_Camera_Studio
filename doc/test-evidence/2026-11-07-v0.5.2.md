# FS Camera Studio 0.5.2 verification record

November 7, 2026. The user requested a new release and chose automatic notifications with installation only
on **Update now**. Live simulator acceptance remains pending, including the MSFS Windows-protocol handoff.

## Build and artifacts

- Source branch: `codex/automatic-updates`, based on 0.5.1 (`956e43c`). One version: 0.5.2.
- Frozen native inputs: `build/release/0.5.2/native-source-freeze.json`. Rebuilt native X-Plane Release and MSFS
  WASM (SDK 1.8.1), compiled the MSFS package, refreshed the reviewed toolbar host and staged 26 MSFS files.
- X-Plane payload: 15 files under `build/auto-updates/xplane/XPCameraStudio`.
- Windows updater built with the .NET Framework compiler, with source and binary hashes recorded under
  `build/updater/verified-build.json`. Installed outside the simulator in a version-specific support directory.
- Shipping and harness setups contain exactly the same simulator payloads and updater binary. They use separate
  app IDs, support folders and URL protocols. The helper is hash-verified by setup, with its hash in BUILD-INFO.
- All 9 distribution assets, ZIP CRC, archived/loose bytes and checksum files verified before publication.
- Manual regenerated: 21 pages, all reviewed in rendered contact sheets; the changed updates page inspected
  at full size. Editor/mini notification screenshots, including 360 px mini width, inspected after fixing an
  overlapping update row. The Windows updater form was rendered off-screen for review; no desktop UI automation.

## Tests

- **323 shared native tests, 76,109 checks** and **8 native keyboard tests, 42 checks** passed.
- **66 UI test files passed**. New coverage exercises automatic startup and periodic checks, cache/dismissal,
  opt-out, no request spam, mini-only sessions, updater launch results, failure fallback and narrow layout.
  The existing X-Plane text assertion was updated for the new wait-for-simulators workflow.
- **38 updater checks passed**, including metadata/version/host validation, no downgrade, wrong or missing
  hashes, truncated/corrupt/oversize downloads, unsafe redirects, HTTP errors, cancellation, waiting for exit,
  installer file locking, re-verification before launch and nonzero setup results. One real official 0.5.1
  installer was downloaded and verified, but NEVER executed by this test.
- **16 isolated installer scenarios passed**. Additional assertions verify the installed updater hash, quoted
  protocol command and removal of both helper and protocol on uninstall. Existing checks cover MSFS/X-Plane
  individually and together, repair, backup integrity, invalid/junction/duplicate targets, process guards and
  preservation of unrelated files. Evidence:
  `build/installer-tests/151daa51-bd9a-4f58-bf46-74b6fb491e2a/results.json`.
- The historical live development-package receipt was absent, so that optional before/after hash check was
  skipped. Tests never targeted real simulator installations. Existing SDK warnings remain.

## Scope of acceptance

The notification and updater logic, real download verification and installer lifecycle have automated evidence.
The production updater has not yet performed a live future-version upgrade from inside either simulator.
In particular, MSFS OpenBrowser handling of the custom Windows URL is pending live acceptance; the UI reports
it as a request and offers Download installer, plus a Start-menu updater shortcut. XPCS has a direct native
launch callback. Neither simulator was controlled through computer-use tools. No user profiles were changed.
The versioned release has not been installed over the user's existing simulator copies by this task.
